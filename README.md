# 票据不说谎 —— 基于多模型交叉校验的票据可信度核验 agent

工行杯全国大学生金融科技创新大赛 · 金融安全服务方向

---

## 一句话

让大模型只负责逐行转写，所有金额汇总交给代码，再用多条相互独立的算术约束
交叉验证同一张票据——识别错了会被发现，人为改过也会被发现。

## 为什么需要它

现有票据 OCR 只做文字识别，不判断票据自身的算术是否成立。于是识别错误与人为
篡改在结果中无法区分，**错误是静默的**：JSON 格式完好、数量级合理，不对照答案
根本看不出来。

更隐蔽的是模型的"自我圆场"。本项目早期版本曾把算术约束写进提示词，要求模型保证
`商品行 - 折扣 = 小计`。模型读错一个数字后，为满足这条约束又改写了第二个数字，
产出一份**自洽但错误**的结果，任何一致性检查都发现不了。
最终设计因此遵循一条铁律：**所有校验只在代码侧执行，从不写入提示词。**

## 四条校验

| | 内容 | 能抓到什么 |
|---|---|---|
| 校验一 | 应付 = 小计 − 小计下方的折扣 + 税费 + 服务费 + 舍入 | 应付金额被改 |
| 校验二 | 商品行总额 − 小计上方的折扣 = 小计 | 单品价格被改，且应付仍闭合 |
| 校验三 | 折扣行标签自带的金额与金额栏一致 | 折扣金额读错（港式票据专有） |
| 校验四 | 付款 − 找零 = 应付 | 付款行或应付行被单独改动 |

折扣是否已计入小计，看它印在小计的上方还是下方：港式票据与 CORD 的单品折扣在上方，
CORD 的整单折扣在下方。模型照抄每条折扣的位置，这是版面事实，不涉及计算。

校验三利用了一个免费的校验位：港式超市折扣行常把金额写进标签本身
（`Buy 3 Save $9.8`、`MB APP UPGRADE -$10`），标签与金额栏互为佐证。
模型只被要求照抄标签文字，并不知道这一项正在被用来判分。

## 数据

| 数据集 | 用途 | 规模 |
|---|---|---|
| [CORD-v2](https://huggingface.co/datasets/naver-clova-ix/cord-v2) (NAVER CLOVA) | 主实验：抽取准确率、自洽率、篡改检出率 | 公开 1000 张（800/100/100） |
| 港式超市票据 | 定性演示：校验三、篡改样例 | 7 张 + 2 张篡改样本 |

CORD 是 Donut (Kim et al., 2022) 等工作使用的票据理解公开基准，标注含
商品行价格、小计、折扣、税费与实付总额，恰好覆盖各条校验所需的全部字段。

## 已完成的测量

`python tests/test_money_and_cord.py`，不需要 API key：

```
金额归一化：18/18 通过

CORD 公开标注实测（34 张）
  menu 为 dict / list：12 / 22
  校验一 小计+税费->总额   适用 21 张，其中自洽 20 张
  校验二 商品行->小计       适用 22 张，其中自洽 19 张
  两条都适用 21 张，都自洽 17 张
```

两点值得注意：

**金额书写必须先归一化。** CORD 内部同时存在 `60.000`、`91000`、`28,000`、
`Rp. 111,000` 四种写法，`.` 和 `,` 都可能是千位分隔符。若按英文习惯把 `60.000`
读成 60.00，六万会变成六十，后续校验全部失效。

**公开数据集上，票据本身并非都自洽。** 21 张两条校验都适用的票据里，有 4 张在
标注层面就对不上（例如整单抵扣的 voucher 记法不同、商品行未标全）。这意味着
"不自洽"作为告警信号存在约 19% 的误报率——这是本方法的固有边界，实验会如实报告
TPR 与 FPR，而不是只报检出率。

## E2 / E3 第一轮：先校准尺子

commit `2fbf8ae`，CORD 两条校验都自洽的前 20 张，每张识别 3 次：

```
E2  小计 19/20   实付 17/20   商品行合计 14/20
E3  被篡改 10 张检出 7   TPR 70%
    未篡改 10 张误报 2   FPR 20%
```

逐张拆开看，问题主要在校验规则本身：

- **2 张误报全部来自公式缺陷。** CORD 31、33 的单品折扣印在小计上方、已计入小计，
  旧公式又扣了一次。拿标注构造逐字无误的转写，离线同样复现这 2 张。
- **检出率取决于改在哪：商品行 / 小计 / 税额 6/6，付款区 1/4。**
  改 CASH 的那张，旧校验里没有一条覆盖付款行；改 TOTAL 的两张，下一行 CASH 仍印原值，
  而旧格式只有一个"实付"栏且允许填 CASH，分辨不出模型照抄了 CASH 还是抹平了 TOTAL。
- **E2 的失分里混着口径问题**：提示词把 CASH 列为实付、把服务费同时列进商品行和服务费栏。

据此改为：折扣按印刷位置区分、应付 / 付款 / 找零分三栏照抄、新增校验四。
以上每个失误样例都已写成离线回归测试（`tests/test_receipt_and_tamper.py`）。

## E2 / E3 第二轮

commit `e01065b`，同样 20 张、同样的篡改目标：

```
E1  CORD test 100 张：一、二都适用 64 张，全部自洽 53 张（标注层面不自洽 17%）
E2  小计 18/20   应付 19/20   商品行合计 18/20
E3  被篡改 10 张检出 9   TPR 90%
    未篡改 10 张误报 0   FPR 0%
```

- **付款区篡改 4/4 检出。** CORD 3、5 的 TOTAL 被改后，模型 3 次都如实报出改后的值。
  第一轮漏检是旧格式让它填了未改的 CASH，不是抹平。
- **唯一的漏检来自投票规则。** CORD 34（税额 8.500→8.700）3 次里 2 次单独判存疑，
  "自洽优先"选了唯一自洽的那次，共识判可信。
- **E2 剩下的失分都是真实误读**，口径问题已消除：CORD 20 读错数字（见下）、
  CORD 30 漏报商品行、CORD 36 没报小计。

**CORD 20：未篡改票据上的"自我圆场"。** 票面 TOTAL 用大字印着 377,859，
其下没有付款行与找零行。第 1 次识别把 47,600 读成 47,400、小计读成 325,400，
报出的应付是 377,659——正好等于按它自己的小计算出的数；还报出了票面上不存在的
CASH 400,000 与找零 22,341（= 400,000 − 377,659）。整份读数完全自洽，四条校验全部通过。
另外 2 次如实报出了 377,859，但投票最终采用的是第 1 次的 377,659。

这说明两件事：模型"让票据平账"的倾向在没有任何篡改时也会出现，而且可以编出整行内容；
"自洽优先"的投票恰好会偏向这种读数。

逐次原始读数证实了机制：CORD 34 的税额 3 次读成 8.500 / 8.700 / 8.700；
CORD 20 的 3 次都把 47,600、325,600 读成 …400，其中 2 次如实报出应付 377,859。
两张都是"自洽优先"让 1 次压过了 2 次。

**投票规则因此改为多数单次判定**：各次识别单独判定，至少一半判存疑即判存疑；
字段值取票数最多的，平票时才参考自洽。在这 20 张上，CORD 34 转为检出，
CORD 20 的误读被告警、应付取回票面的 377,859。旧规则保留为 `rule="consistent"`，
E3 在同一批读数上并列输出两种规则的结果。

**样本量提醒**：以上都是 20 张、10 张篡改的量级，差 1 张就是 10 个百分点。
而且两轮的规则修正都是看着这 20 张做的（开发集），最终数字须在其余 33 张自洽票据上
只跑一次（留出集）。notebook 默认已指向留出集。

## 最重要的一个发现：模型会自发掩盖篡改

把两张被改过的港式票据送进整票转写，结果是：

| 篡改 | 模型报回来的 | 实际发生了什么 |
|---|---|---|
| 付款行 316.10 → **816.10** | 316.10 | 拒绝报告不合理的付款额，替换成自洽的值 |
| 商品行 91.80 → **98.80** | 商品行合计仍是 392.20 | 如实报出被改的 98.80，却把**另一行** 22.90 改写成 15.90 来对冲 |

提示词里没有任何等式——**这是模型自带的「票据应当平账」先验**。
更关键的是，明确加上"这张票可能已被人为改动，照抄不要修正"之后，
付款行那例**依旧**报 316.10。这排除了"提示词写得不够严"这个解释。

只要转写阶段就把数字抹平，下游任何校验都不可能发现篡改。

### 解法：按行转写

模型能对冲，前提是它同时看见整张票。把视野裁到单行，它就没有可对冲的对象：

| 转写方式 | 付款行 →816.10 | 商品行 →98.80 |
|---|---|---|
| 整票转写 | 被抹平 | 时好时坏 |
| 整票 + 告知可能被改 | **仍被抹平** | 时好时坏 |
| **单行裁剪转写** | **照抄** | **照抄** |

单行转写在两个案例上各两次、四次全部照抄。这不是提示词问题，是架构问题：
产品必须**先分行、再逐行读**，而不是一次读一整张。

**适用范围要说清楚。** 抹平篡改目前只在这两张港式样本上观察到（字形复制，付款行虚增 500）。
CORD 上的整块重绘篡改，TOTAL 被改后模型 6 次读数全部如实报出（见下文第二轮）。
但同样的"平账"倾向在 CORD 20 这张**未篡改**票据上出现了：一次误读之后，
模型改写了应付，还编出了不存在的付款行。

实验见 `experiments/e5_line_level.py`。

## 局限

这套机制查的是**票面算术是否自洽，不是像素取证**。造假者若把商品行、小计、
付款行一并改成彼此吻合的数字，各条校验都会通过。它提高的是伪造成本：
要同时骗过多条相互独立的约束，远难于改动单个数字。

模型漏报小计或应付时，对应的校验判为不适用，不用其他字段倒算补上——倒算出的数必然自洽，
会让校验空转通过。一条校验都不适用的票判「无法核验」，不默认可信。

多数判定的代价：若模型对某张票的误读是稳定的（3 次读错同一处且都自洽），投票救不回来。
按行转写要解决的正是这种情况。
